# CSV-результаты

Экспорт содержит три файла UTF-8 с заголовками. Десятичный разделитель — точка. Неопределённые величины записываются пустыми полями; счётчики при пустой выборке равны нулю. Строковые поля с запятой, кавычкой или переводом строки заключаются в кавычки; внутренняя кавычка удваивается.

Старые имена и порядок начальных столбцов сохранены. Новые столбцы добавлены справа. Все три файла связываются по `scenario_id` и `repetition`; `seed` не является уникальным идентификатором запуска, поскольку одинаковые seed используются в сравниваемых сценариях.

## Идентификация запусков

`CsvResultsWriter.write(directory, runs)` экспортирует список как сценарий `baseline`, назначая номера повторов от 1 в порядке списка. Поэтому текущий `SimulationMain`, выполняющий seed 1–30, сохраняет соответствующие номера повторов 1–30. Параметры берутся из конфигурации каждого фактически выполненного запуска, включая локальные изменения `SimulationConfig.baseline()`.

Для произвольных сценариев используйте `writeExperiments`:

```java
var result = new SimulationRunner().run(config, seed);
CsvResultsWriter.writeExperiments(directory, List.of(
        new ExperimentRun("K=5", 1, result)
));
```

`repetition` должен быть положительным, а `scenario_id` — непустым. Дублирующаяся пара «сценарий — повтор» отклоняется до записи файлов. Разные сценарии могут использовать одинаковые seed и номера повторов.

## runs.csv

| Столбцы | Значение |
| --- | --- |
| `scenario_id`, `repetition`, `seed` | Сценарий, номер повтора и seed типа `long` |
| `status`, `completed_generations` | `completed` или `extinct`; число завершившихся поколений, включая поколение, закончившееся вымиранием |
| `side_length`, `population_size` | Сторона мира `L` и исходная численность поколения `N` |
| `maximum_generations`, `ticks_per_generation`, `rounds_per_match` | Лимит поколений `G`, тактов `T` и число раундов `K` |
| `initial_energy_hundredths`, `resource_energy_hundredths`, `living_cost_hundredths` | `E0`, `R`, `c` в сотых единицы энергии |
| `resource_spawn_probability` | Вероятность восстановления `q` |
| `game_payoff_weight_hundredths` | Вес `α` в сотых: значение 20 означает 0,20 |
| `crossover_probability`, `mutation_probability`, `tournament_size` | `pc`, `pm`, размер турнира |
| `model_version`, `random_generator`, `java_version` | Версия правил `genetic-v1`, фактически используемый генератор `L64X128MixRandom`, версия Java при расчёте |
| `extinct`, `extinction_generation` | Факт вымирания и номер поколения; номер пустой для завершённого запуска |
| `pairing_mode` | `local` — базовые пары из соседей; `global` — экспериментальный случайный партнёр из всей живой популяции. Последний столбец; в старых результатах отсутствует (локальный режим) |

Версия модели относится к правилам, а не к параметрам сценария. Изменение параметров не меняет `model_version`; полная конфигурация сохраняется в той же строке. Сведения о среде записываются в `SimulationRunResult` и сохраняются при последующем экспорте результата.

## generations.csv

Одна строка измеряется после последнего фактически выполненного такта поколения и до создания потомков. Суммы игр и ресурсов включают всё поколение, в том числе вклад агентов, погибших до его конца. Между поколениями накопительные счётчики сбрасываются.

| Столбцы | Значение |
| --- | --- |
| `seed`, `scenario_id`, `repetition`, `generation`, `ticks` | Идентификация запуска, поколение и число выполненных в нём тактов |
| `living_agents`, `survival_fraction` | Число выживших `S` и `S / N` |
| `average_energy_hundredths`, `maximum_energy_hundredths` | Средняя и максимальная энергия выживших; пустые при `S = 0` |
| `resource_energy_hundredths`, `average_resource_energy_hundredths` | Суммарная энергия от ресурсов и её отношение к исходной численности `N` |
| `game_payoff`, `average_game_payoff` | Суммарный сырой игровой выигрыш и его отношение к `N` |
| `game_energy_hundredths` | Энергетический вклад игры: `game_payoff_weight_hundredths × game_payoff` |
| `matches`, `played_rounds` | Число встреч и число раундов всех встреч |
| `first_round_cooperative_actions`, `first_round_actions` | Число действий `C` в первых раундах и число действий обоих игроков: `2 × matches` |
| `first_round_cooperation_rate` | Отношение двух предыдущих счётчиков; пустое без встреч |
| `cooperative_actions`, `played_actions`, `cooperation_rate` | Число действий `C`, число всех действий (`2 × played_rounds`) и их отношение |
| `cc_count`, `cd_count`, `dc_count`, `dd_count` | Количества исходов раундов; первый игрок — агент с меньшим `agentId` |
| `cc_fraction`, `cd_fraction`, `dc_fraction`, `dd_fraction` | Доли исходов среди `played_rounds`; пустые без раундов |
| `spatial_clustering` | Доля соседних неупорядоченных пар с одинаковыми генотипами среди всех занятых соседних пар; пустая без пар |
| `extinct` | Поколение завершилось вымиранием |

Доли сотрудничества учитывают действия **обоих** игроков и лежат в диапазоне 0–1. Например, одна встреча `C` против `D` в единственном раунде даёт 1 действие `C` из 2 действий и долю 0,5. Сумма долей `CC/CD/DC/DD` при наличии раундов равна 1.

Кластеризация измеряется в окрестности Мура с тороидальными переходами. Используются направления вправо, вниз, вниз-вправо и вниз-влево: каждая неупорядоченная пара учитывается один раз, включая пары через края мира.

Суммарные выигрыши, энергия и игровые счётчики хранятся в `long`, чтобы длительные поколения не переполняли 32-битные суммы. Энергия отдельных агентов сохраняет исходный целочисленный тип модели.

## genotype-frequencies.csv

Столбцы: `seed,generation,genotype,count,frequency,scenario_id,repetition`.

Для каждого поколения записываются все 32 генотипа в фиксированном порядке, включая отсутствующие. `count` — численность генотипа среди выживших, `frequency = count / S`. При вымирании все численности равны нулю, а частоты пустые. Пять символов генотипа соответствуют `g0, gCC, gCD, gDC, gDD`.

## Воспроизводимость

Для одинаковых параметров, seed, порядка сценариев/повторов, версии модели и среды выполнения CSV воспроизводится побайтно. Расчёт метрик не использует генератор случайных чисел и не меняет порядок фаз симуляции. Повторный экспорт в одну папку перезаписывает три CSV-файла.
