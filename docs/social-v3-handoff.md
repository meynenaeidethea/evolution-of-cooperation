## Обязательные решения, которые нельзя потерять

- V2 остаётся отдельным режимом и точным эталоном старых seed.
- V3: непрерывная жизнь, один родитель, платное местное рождение, возрастная смерть,
  без восстановления N и бесплатной еды из смерти.
- Один конечный ресурсный запас клетки. Личная добыча и совместная PD используют
  его; B0=5*h, общий u=floor(B/(10K)), из поля списывается D=10Ku.
- Энергетический ledger точный, все добровольные расходы требуют E>cost;
  восстановление нулевого агента поздней добычей запрещено.
- Пять наследуемых генов не переписываются обучением. Память по ID, 16 Q-оценок,
  личное обучение и одна культурная строка — разные состояния.
- Местное восприятие, фиксированная объяснимая функция движения, outside option
  личной добычи и точная формула оценки партнёра.
- Приватная память ограничена, teacher summary объявляется локально и честно;
  копирование не даёт всеведения, переносы не каскадируют внутри такта.
- Культурный ключ [CD?]{8}; ties не превращать в случайно меняющиеся метки.
- Контактный наблюдатель независим от M, иначе результат о группах будет круговым.
- H1 placebo переставляет только временное представление ID; реальные записи и
  observer events не портятся.
- H2/H3 используют заранее указанные difference-in-differences; для H3 есть
  sham natural-fast. H4 ветвится только после одинаковой предыстории.
- Состояние S_t, действие tau=t+1, birthTick=tau, первичная запись ребёнка с возрастом 0.
- RNG фазовый, формула/ID/четыре hex-вектора определены; v2 RNG не менять.
- UI-запись включена по умолчанию; при её явном отключении до нового запуска —
  только live, без обещания полной истории. Batch по умолчанию без кадров.
- Полный просмотр не объявляется exact resume. Старый .eoc v1 продолжает читаться.
- Ядро/интерфейс/анализ суммарно ориентированы на ≤3500 новых production LOC,
  без runtime-зависимостей; численные гипотезы не оправдывают разрастание кода.

## Первый рабочий цикл M0/M1

1. Проверить clean status, доступность JDK и существующие инструкции.
2. Запустить прежний build; сохранить исходный отчёт как baseline вне Git.
3. Подготовить маленькие детерминированные fixtures для конечной энергии,
   рождения в соседней клетке, смерти, недоступной цены действия и бюджета CC/CD/DD.
4. Реализовать конкретные SocialConfig/SocialField/SocialState/SocialSession
   и минимальный headless запуск с отключёнными обучением/культурой.
5. Применять соседние механики только после точного баланса и повторяемости.
6. Отчёт M1: изменённые файлы/LOC, реальные команды, результаты проверок,
   что ещё не реализовано из M2–M6. Коммит M1 не включает выдуманное исследование.
7. Продолжить по §20, не разрабатывать UI/анализ раньше стабильной семантики данных.

Команды базовой проверки из корня:

```sh
./gradlew :simulation:build
STUDY_TEST_INPUT=results/interactive-regression-20261103 .venv/bin/python -m unittest discover -s tools -p 'test_*.py'
sha256sum -c docs/results/main-protocol.sha256
git diff --check
```

Если локальных CSV-fixtures нет, создать новые короткие технические серии по CI,
не подставлять старые научные результаты в тест как будто это новый расчёт.
Для реальной UI-проверки читать текущий smoke workflow: переделывать его на два
явных режима, сохраняя проверку старой демонстрации, а не ломать её ожидания молча.
`--offline` использовать, когда зависимости уже доступны; не считать отсутствие
кэша ошибкой модели. Закреплённые Python зависимости — tools/requirements-analysis.txt.

Нужны содержательные тесты, а не максимальное число тестов. После прошедших
проверок не запускать один и тот же широкий набор без новой причины.

## Оркестрация и экономия моделей

Пользователь явно попросил оркестрацию и `gpt-6-luna` для простых задач.

- Координатор сохраняет текущую сильную модель для физики, фазового порядка,
  причинных сравнений, совместимости и окончательного code review.
- `gpt-6-luna`: инвентаризация, ограниченные profile/CSV-fixtures, документация,
  проверка ссылок, механические преобразования с чётким контрактом.
- Сильные реально доступные модели FreeLLMAPI: независимая критика конкретного
  дизайна/патча, проверки математики и причинных выводов. Нельзя выбирать модель
  только по привлекательному alias без проверки фактически обслужившего провайдера.
- Для `spawn_agent` с model override использовать `fork_turns="none"`, короткий
  self-contained prompt, точные файлы, критерии и владение. Не копировать всю историю.
- Не более двух работающих субагентов одновременно в дополнение к координатору;
  на маленькой последовательной задаче субагент не обязателен.
- Один агент владеет изменением SocialSession/схемы на данном шаге; другим давать
  read-only review или отдельные файлы. Итог интегрирует координатор.
- LLM-ответ является предложением, не тестом и не научным наблюдением. Проверять
  кодом/данными и первоисточниками. Не добавлять LLM в поведение агентов мира.

### Точный статус FreeLLMAPI при передаче

Проверял отдельный субагент `gpt-6-luna`, затем выполнена дополнительная проверка.

- Локальный gateway/dashboard отвечает на `http://127.0.0.1:3001/`.
- `GET /v1/models` без авторизации возвращает HTTP 401.
- В доступных service env есть ENCRYPTION_KEY/PORT/HOST_BIND, а API token не найден;
  это не повод подменять API-ключ ключом шифрования.
- `sudo -n docker ps` требует пароль; учётные данные не сбрасывались.
- Доступного authenticated browser нет: computer-use inventory вернул отсутствие
  браузеров и недоступность browser host. Browser storage/cookies не извлекались.
- Default model/provider Codex и существующий gateway не менялись.
- Внешние модели FreeLLMAPI ещё НЕ использовались. Их качество/доступность в этом
  экземпляре не проверены; нельзя писать «проверено лучшей моделью FreeLLMAPI».

Если в новой сессии появится `FREELLMAPI_API_KEY`, использовать его только через
секрет окружения, не выводить в stdout/аргументы/файлы проекта. Проверить live
каталог и возможности, сделать короткий smoke request, сохранить только безопасный
model id и X-Routed-Via, убедиться в разрешённом бесплатном маршруте без paid fallback.
Никаких сбросов auth, поиска browser cookies или новых платных/внешних аккаунтов.
При продолжающемся 401 не задерживать разработку и не изобретать «обход»; использовать
доступные native-модели. Этот операционный блокер не меняет ТЗ модели.
Настроенный позднее профиль должен быть отдельным optional profile, не заменой
глобальных настроек/основной модели. Документация шлюза:
<https://github.com/tashfeenahmed/freellmapi/blob/main/docs/en/api/01-rest-api.md>.

## Границы пилота и исследовательского результата

Не выполнять 360 подтверждающих запусков до M5 и заморозки протокола.
Сначала энергетика/нагрузка и невырожденность по объявленным критериям.
Маленькая картинка и два seed не подтверждают H1–H4.
Не исключать вымершие миры и миры без красивых сообществ. В данных должны быть
стоимости, охват, отсутствие финансирования, культурные переносы и нулевые эффекты.
Не увеличивать число гипотез/метрик после просмотра без маркировки exploration.

Технически полезный отрицательный результат — например, культура не помогает
при выбранной цене общения — публикуется с теми же проверками. Пользователь
просил интригующие и верифицируемые результаты, а не гарантированное подтверждение.
