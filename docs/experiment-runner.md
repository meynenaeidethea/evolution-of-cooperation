# Запуск серий экспериментов

`ExperimentPlan` строит набор конфигураций на основе переданного `SimulationConfig`. `ExperimentSeriesRunner` последовательно выполняет независимые запуски через существующий `SimulationRunner` и экспортирует данные через `CsvResultsWriter`. Графическое окно и история снимков при этом не создаются.

Базовая конфигурация не меняется и не заменяется параметрами из спецификации. Каждая сравнительная конфигурация отличается от неё ровно одним фактором. `L`, `N`, `T`, `G`, начальная энергия, стоимость жизни, скрещивание и размер турнира сохраняются во всех сценариях. При новом выполнении серии исходные значения снова читаются из `SimulationConfig.baseline()`.

## Доступные серии

В каждой серии первым выполняется `baseline`. Если точка сравнения уже совпадает с базовой конфигурацией, отдельный дублирующий сценарий не создаётся. В `all` базовый сценарий также выполняется только один раз и используется как общий контроль.

| Значение `--series` | Изменяемый фактор | Точки сравнения | Идентификаторы вариантов |
| --- | --- | --- | --- |
| `baseline` | Нет | Ваша конфигурация | `baseline` |
| `rounds` | Раунды игры `K` | 1, 3, 5, 10 | `rounds-1`, `rounds-3`, … |
| `game-weight` | Вес игрового выигрыша `α` | 0; 0,10; 0,20; 0,35; 0,50 | `game-weight-0`, `game-weight-10`, …; суффикс в сотых |
| `mutation` | Мутация одного гена `pm` | 0; 0,005; 0,01; 0,02; 0,05 | `mutation-0`, `mutation-5`, …; суффикс в тысячных |
| `resource-spawn` | Вероятность восстановления `q` | 0,02; 0,05; 0,10; 0,25 | `resource-spawn-2`, `resource-spawn-5`, …; суффикс в сотых |
| `resource-energy` | Энергия ресурса `R` | 2; 4; 8 | `resource-energy-200`, …; суффикс в сотых энергии |
| `locality` | Выбор игрового партнёра | Локальный / из всей живой популяции | `baseline`, `pairing-global` |
| `all` | Все перечисленные сравнения | Объединение, без дубликата базового сценария | Все соответствующие идентификаторы |

Точки `K`, `α` и `pm` взяты из плана экспериментов. Для `q` и `R`, где план задаёт диапазоны, выбраны приведённые выше точки внутри диапазонов спецификации. Если ваша базовая конфигурация содержит другое значение, оно остаётся дополнительной контрольной точкой.

Число сценариев зависит от совпадений с вашей базовой конфигурацией. Перед запуском `--list` выводит полный набор параметров каждого сценария и общее число запусков. Это фиксирует `T` и `G` вместе с остальными параметрами перед расчётом.

## IntelliJ IDEA

Обновите Gradle-проект и запустите класс `evolution.experiment.ExperimentMain`. **Program arguments**:

```text
--series rounds
```

Без аргументов выполняется `baseline` с 30 повторами. `SimulationMain` и `SimulationVisualMain` остаются отдельными точками входа.

## Терминал

Посмотреть план без расчёта и без записи файлов:

```sh
./gradlew :simulation:runExperiments --args='--series all --list'
```

Выполнить все поддержанные сравнения с 30 повторами:

```sh
./gradlew :simulation:runExperiments --args='--series all'
```

Указать новый каталог для результатов:

```sh
./gradlew :simulation:runExperiments --args='--series mutation --output results/mutation-study-01'
```

Короткая проверка работоспособности с одним повтором:

```sh
./gradlew :simulation:runExperiments --args='--series rounds --repetitions 1'
```

Справка:

```sh
./gradlew :simulation:runExperiments --args='--help'
```

Задача Gradle использует JDK 25 и запускает приложение с рабочей директорией в корне проекта. При запуске из IntelliJ относительные пути отсчитываются от рабочей директории конфигурации запуска. Задача использует стандартный [JavaExec Gradle](https://docs.gradle.org/current/dsl/org.gradle.api.tasks.JavaExec.html).

`--repetitions` должен быть положительным целым числом; по умолчанию — 30. В каждом сценарии seed равен номеру повтора, то есть используется один и тот же набор `1…N`. Значение меньше 30 предназначено для проверки; программа сообщает, что такая серия не выполняет требование плана исследования по числу повторов. Вымирание отдельного запуска записывается в CSV и не останавливает следующие повторы.

## Результаты и прогресс

По умолчанию создаётся новый каталог `results/experiments/<серия>-<дата-время>`. Явно заданный `--output` также должен указывать **несуществующий** каталог; даже пустой существующий каталог отклоняется, чтобы результаты предыдущей серии не перезаписывались.

```text
<каталог серии>/
  baseline/
    runs.csv
    generations.csv
    genotype-frequencies.csv
  rounds-1/
    runs.csv
    generations.csv
    genotype-frequencies.csv
  ...
  runs.csv
  generations.csv
  genotype-frequencies.csv
```

После завершения каждого сценария сохраняются его три CSV. После всей серии в корне появляются три общих CSV с результатами всех сценариев. В каждом файле сохраняются `scenario_id`, `repetition`, seed и метрики согласно [формату CSV](csv-results.md). В `runs.csv` также находится полная конфигурация и среда каждого запуска.

Консоль показывает количество завершённых запусков, сценарий, повтор, seed, статус и число завершившихся поколений. Если серия прервана, CSV полностью завершённых сценариев остаются в их подкаталогах. Повторы текущего незавершённого сценария находятся только в памяти; общие CSV записываются после завершения всей серии. Автоматическое продолжение прерванной серии пока не поддерживается.

## Контроль локальности

```sh
./gradlew :simulation:runExperiments --args='--series locality'
```

В `baseline` партнёры выбираются среди соседей по неизменным правилам базовой модели. В `pairing-global` живые агенты равномерно перемешиваются и разбиваются на последовательные непересекающиеся пары; при нечётной численности один случайный агент остаётся без игры. Каждый агент играет не более одного матча за такт, первым игроком остаётся агент с меньшим `agentId`. Движение, ресурсы, энергия, генетика и все параметры `SimulationConfig` сохраняются. Режим передаётся отдельно через `PairingMode`; обычные пакетный и графический запуски по умолчанию локальны. `all` включает этот контроль.

В `runs.csv` добавлен последний столбец `pairing_mode` (`local`/`global`), прежние столбцы не перемещаются. Нелокальный режим меняет не только состав партнёров, но и частоту встреч: почти каждый живой агент получает игру каждый такт. Поэтому результат следует интерпретировать как эффект режима взаимодействий, а не как чистый эффект пространственной кластеризации при одинаковом числе игр. Одинаковые seed обеспечивают воспроизводимость, но не идентичные последовательности движений между режимами: расход случайных чисел при составлении пар различается.

## Анализ

Сам запуск серии не формулирует исследовательские выводы. Для готовых CSV доступен [отдельный анализатор](results-analysis.md), строящий графики, статистические сводки и парные доверительные интервалы без перерасчёта модели.

Автоматические тесты проверяют сохранение исходной конфигурации, изменение одного фактора, общий набор seed, воспроизводимость CSV, сохранение завершённых сценариев, обработку вымирания, аргументы запуска и защиту существующих каталогов. Проверки выполняются на коротких явно заданных конфигурациях и не требуют графического окна.
